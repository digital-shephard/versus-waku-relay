# FX Phase 2 Admission Journal

Status: local research only
Production FX: disabled

`src/fx-admission-journal.mjs` is an independent relay-side implementation of
the Phase 1 signed FX protocol's Phase 2 admission rules. It is deliberately not
imported by `src/main.mjs`.

It verifies:

- message signatures and canonical IDs
- deployment and trade domains
- sender sequence monotonicity and equivocation
- economic action nullifiers
- RFQ, quote, acceptance, reservation, lock, claim, refund, and completion
  lineage
- deterministic route recomputation
- exact beneficiary, amount, token, hash, and timeout relationships

The frozen transcript in `fixtures/fx-phase2-transcript.json` is generated by
the client simulator. The relay replays it through repeated process
construction and must produce the exact client state hash:

`0xeb6b70cbb04b304b9153bb18a52369c694ecf952d6687d39476186aad33673ba`

Run:

```powershell
node --test test/fx-phase2-admission.test.mjs
```

This journal uses atomic file replacement and fails closed on corruption or a
deployment mismatch. It is suitable for deterministic Phase 2 parity testing,
not production throughput. A later Waku phase must move active trade admission
to a bounded transactional store and preserve these vectors.
